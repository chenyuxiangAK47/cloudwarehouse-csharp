============================================================
TASK B — 非内网环境把 Demo 跑通（给 App Demo / Value Added 录屏用）
============================================================

背景：
工厂演示原来走内网（PDA → 内网 Spring Boot → SQL Server）。
现在要在**家里/宿舍/非工厂内网**录 NUS App Demo：登录 → 选机 → 开工 → 报工成功。
请想办法给出一条可重复的非内网演示路径。

目标（验收标准）：
在非内网机器上，用真机或模拟器完成一次闭环，并留下可录屏证据：
登录成功 → 选产线/机台 → 开工成功 → 报工成功（界面有成功反馈）。

允许方案（按可行性选，优先简单可录）：
方案 1（推荐）：本机同时跑 SQL Server（或 Docker SQL）+ Spring Boot，手机/模拟器走可路由地址
  - Android 模拟器访问宿主机常用 `10.0.2.2:端口`
  - 真机与电脑同一 Wi‑Fi，用电脑局域网 IP（注意防火墙放行端口）
方案 2：本机 API + Cloudflare Tunnel / ngrok 暴露 HTTPS/HTTP，App 指到公网临时 URL（演示完可关）
方案 3：若已有 mock flavor（仓库里似乎有 mockDebug），用 mock 打通 UI 演示；但报告/视频需诚实说是 demo/mock，并尽量仍展示真实 API 路径之一
方案 4：无法装 SQL 时，用 H2/Testcontainers 仅作演示库（若改动小）；不要大重构

必做：
1. 摸清当前 App 的 API Base URL 配在哪（build flavor / strings / constants），做成**可切换**的 demo 配置，不要把工厂内网 IP 写死成唯一默认
2. 准备一份 `docs/DEMO-OFFLINE.md`（或根 README 一节）写清：
   - 前置：JDK、SQL、端口、示例账号/员工码（可用演示账号，勿写生产密码）
   - 启动 API 命令
   - App 如何指向该 API
   - 录屏点击路径：登录 → 选机 → 扫/输批号开工 → 报工
3. 实际在非内网跑通一次；失败就修到能通，或给出明确阻塞原因 + 次优录屏方案（例如稳定历史录屏 + 当前 API 健康检查页）
4. 扫码：无 Honeywell 真机时，允许手工输入批号/图号；文档写明

不要做：
- 不要为了 demo 宣称已和 CloudWarehouse 打通
- 不要把生产/工厂数据库暴露到公网长期不关
- 不要提交隧道 token、DB 密码进 git

交付物（完成后回复用户）：
- 最终采用的方案编号
- 一步步怎么在非内网启动（命令级）
- App 改了哪个配置文件/字段
- 是否已真的跑通闭环（是/否 + 截图或录屏文件路径）
- 若只能部分跑通：卡在哪、录视频时怎么说才诚实
