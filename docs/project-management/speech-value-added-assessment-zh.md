## PDA 可吹点清单（答辩备用，口播不必全念）

按杀伤力排序：

1. **硬件集成**：霍尼韦尔工业 PDA + 扫码 SDK/楔入——车间终端，不是手机网页玩具  
2. **真痛点**：正式工单未下发也能开工/报工（夜班、插单、无 ERP 工单）——shop-floor digitization  
3. **端到端闭环**：PDA → Spring Boot API → `PDA_NoOrder`，并 **双写** 老 MES `mes_busi_workorder_report`（批号、工序、机台、实际/标准工时、时间）  
4. **业务规则**：挂起/续开（可换机）；报工对齐最近开工机台；标准工时机台→产线→图号+工序；工序校验与点选防乱输  
5. **数据质量**：异常巡检（错栏、工时异常、超时未报工）——operational excellence  
6. **工程细节**：连扫叠字、`XK|` 前缀、光标在中再扫整框替换、版本更新提示、内网下载页  
7. **multi-app**：云仓 Billing；PDA Execution——先各自做厚，再谈集成

挡话：  
「当前是 multi-app 交付：执行域与结算域各自闭环；集成是下一阶段，不稀释本阶段已交付的增值。」

## 演讲稿（照着念）

### 0. 封面 · 约 30 秒  
**【展示：封面】**

各位老师好。本视频是 **Value Added Assessment**。  

一句话定位：本实习的增值，是把工厂里两条本来靠 Excel 和口头撑着的链路做成可运行系统——仓库侧可审计的运费结算，以及产线侧把 **夜班/临时加工这条游离在 MES 外的数据采集**，做成可扫码、可落库、可对账、可巡检的现场操作系统。  

下面按问题、云仓增值、PDA 增值与边界说明。

---

### 1. 增值要解决什么问题 · 约 40 秒  
**【展示：痛点对比页】**

仓库侧：运费靠 Excel，历史价说不清，对账对不上。  
产线侧：无正式工单时靠纸笔或口头，产量与工序难追溯，MES 主流程覆盖不到。  

增值目标：  
- 结算从“表格猜测”变成“规则 + 引擎 + 对比证据”；  
- 现场从“口头记一笔”变成“扫码采集 + 规则约束 + 库表可审计”。  

这不是两个 CRUD demo，而是结算域与执行域的数字化补强。

---

### 2. 企业能力拼图 · 约 35 秒  
**【展示：16 Context Map】**

Context Map：CloudWarehouse = Billing & Pricing；PDA = Shop-floor Execution。  
实线已交付；虚线是规划集成。  
叙事是 **enterprise multi-app landscape**：先把上下文做厚，再谈打通——比空喊微服务更站得住。

---

### 3. 云仓增值点一：历史价 + 双轨对账 · 约 65 秒  
**【展示：运单预览/对比结果】**

云仓硬增值之一：**按发货日取历史成本/报价**，再做 **应收 vs 应付双轨**。  

账单中转费往往对应账单期间价格，不是今天最新价；永远取最新价会造成系统性偏差。  
引擎按生效/失效版本计价，运单预览与表内金额对比：大量对齐，少数失败为退件/拦截等无目的省——可解释，非黑盒。  

增值落地为财务可信：对得上，对不上也说得清。

---

### 4. 云仓增值点二：规则检索（可用、不装神）· 约 40 秒  
**【展示：计价规则检索 Tab】**

内置 **计价规则检索**：示例问题快速查阅双轨、取整、导入、Strategy 说明。  

边界：assistive lookup（关键词/TF-IDF，可选 LLM 改写），有引用与低分未命中；  
**不参与正式计价**，真相源仍是 FeeCalculationEngine。  
增值在可用性，不在虚构“AI 计费”。

---

### 5. PDA 增值：现场操作系统 · 约 80–85 秒  
**【展示：PDA 录屏；有则切异常巡检截图 3–5 秒】**

并列增值在产线侧：基于 **霍尼韦尔工业 PDA** 的 MES **无订单报工**。  

工厂痛点很具体：夜班或临时加工没有正式工单时，传统靠纸笔或口头，产量与工序难追溯。我们交付的不是演示页，而是一条可运行闭环：工人在手持终端登录、选择产线机群机床，扫码或录入批号完成开工与报工；数据经 Spring Boot API 写入自建库，并 **同步进入 MES 报工结构**，形成财务/MES 侧也能看见的流水。

技术与业务增值叠在一起：  
- **硬件扫码集成**贴合车间，而不是手机网页玩具；  
- **挂起/续开**支持换机，但 **报工强制对齐最近开工机台**，避免错机污染；  
- **标准工时**按机台映射产线后再对照图号工序写入，服务后续工时分析；  
- 针对扫码叠字、错栏等现场脏数据，做了交互约束与 **异常巡检**——增值落在 **可采集、可约束、可审计**，不是只做一个能点的按钮。

它与云仓结算形成前后场互补：一边把费用对清楚，一边把现场产量记清楚。  
两套系统当前 **未做生产级 API 打通**，但各自上下文已经足够支撑 Value Added 叙事。

---

### 6. 边界与收束 · 约 45 秒  
**【展示：收束页】**

诚实边界：未与云仓生产级打通；不做数字孪生/微服务全家桶叙事；不做 AI 自动报工；规则检索不替代结算引擎。  

挡话：当前是 **multi-app 交付**——执行域与结算域各自闭环；集成是下一阶段，不稀释本阶段已交付的增值。  

Value Added 收束——尤其 PDA 三句：  
1. 把无工单现场从口头记忆变成 **可追溯数字流水**；  
2. 用 **硬件 + 规则**，把采集质量做进流程，而不是事后催人改表；  
3. 与云仓并列，构成 **结算—执行双轨数字化拼图**。  

以上是 Value Added Assessment，谢谢。
